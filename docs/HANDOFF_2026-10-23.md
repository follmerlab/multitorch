## The headline: the trigonal half-integer path is impossible, not unfinished

Residual 68. D3's double group has two **one-dimensional** spinor irreps
forming a complex-conjugate pair — Frobenius–Schur indicator **0**, where every
D4h double irrep is pseudo-real at **−1**. A complex Hermitian block is
reducible to real symmetric by a diagonal phase transformation iff every loop
product `H_ij H_jk H_ki` is real, and a loop product is **invariant under
exactly that freedom** — which is the whole freedom gauge-fixing has, one phase
per route and one per copy. D3d's E1/2 block passes at 4.6e-14; its `1E3/2`
block fails at **9.9e-01**.

So there is no gauge to find, and the RAC store holds real coefficients.

**What a fix would be**, measured: `H(2E3/2) = conj(H(1E3/2))` to 1.9e-15 with
equal eigenvalues (Kramers), and the **pair together** has an exact real form of
twice the dimension while neither member alone does. So the Kramers pair would
have to be carried as one two-dimensional **corepresentation**, or the store
would have to hold complex coefficients. Either is a data-model change, not a
convention. Butler does not settle it: his `sum(dim²) = 12` counts the pair as
two 1-D irreps, so the pairing lives in the 2jm/3jm data residual 61 established
is unreadable.

**Be honest about the guard.** Removing the refusal does not expose a wrong
number — the code still fails, with `RuntimeError: this basis was built without
d4h=True`, which blames a missing flag. The guard converts a misleading error
into an accurate one; it prevents confusion, not silent wrongness.

### Four findings that changed what the work was

1. **Residual 34 was the smallest of three defects in the same twenty lines.**
   The one that corrupted output was on no list: a `max(z_triad, 1e-30)` floor
   destroyed the scale invariance of `calcDOC`'s per-triad ratio, so a
   thermally depopulated triad reported `0.000000` — **8 of Ni(II) Oh's 12
   triads**. ttban prints the same quantity per BAND and nothing had compared
   them; it now agrees to ≤3.0e-06 against an absolute error of up to **0.92**.
   Residual 34's own double count measures ≤4.7e-06 and is in a second path the
   residual does not name.

2. **The dipole caveat was pointing at the wrong function.** The dipole is
   dimension-general because it reads partner extents off the tensor and
   carries dimension through `‖T‖_F` — Fortran-validated on absolute
   intensities at extents 2, 4 and mixed 2×4. What is tetragonal-only is
   `GaugedBasis.target_partners`, which residual 62 did **not** widen.

3. **The route phases are pure gauge.** Scrambling them moves max |Im| from
   5e-16 to 1.28 while eigenvalues move 2.2e-16; flipping a pinned sign moves
   individual stored coefficients by up to **10.8** while every per-block
   intensity sum stays bit-identical. So the descent limit, Kaizaki and the
   spectrum are all **blind** to them by construction.

4. **D3d integer-J was mostly already done.** `gauged_basis` is called only for
   half-integer J, so the route-phase question — the brief's "hard part" — was
   irrelevant to the deliverable.

## What to be careful of

**The suite does not catch an ordering change on the half-integer D4h path.**
Increment E silently moved **1303 of d4h d7's ADD entries** and the whole suite
stayed green; it was caught only by dumping coefficients before and after and
comparing. There is no Fortran fixture for tetragonal odd-electron ions, which
is why. `/private/tmp/.../scratchpad/dump_coeffs.py` is the shape of that check
— **re-create it and run it before and after any change to the generator.**
The cause was that `_pin_d4h_routes` pins each phase against the *first*
coupling it finds, so the operator iteration order is load-bearing for parity
even though the phases are gauge. That order is now pinned by a test with its
reason.

**Residual 45's discipline paid for itself three times this session.** Every
generalization was gated at exact equality against the function it generalized,
and the tetragonal original was retained as the oracle rather than deleted:
`oh_to_target_double_subduction` (0.0 on all four routes), `target_basis_layout`
(0.0 on all four even counts, both parities), and the operator vectors
(`cf_operator_vector('D4h', …)` bit-identical to `_d4h_operator_vector_complex`).

## Conventions (unchanged, and they earned it again)

Every physics change needs a Fortran, analytic or finite-difference oracle —
never code-vs-code. **A new oracle isn't an oracle until you inject the bug
it's meant to catch and watch it fail** — this session that discipline caught a
drift guard with no teeth (three attempts), dead code applying a convention
twice, and a test whose premise had inverted. Commit to `develop` after each
increment with a green suite, staging files explicitly. **Ask before pushing
and before merging to `main`; never run fits locally.** Restore an injected bug
from a file backup, not `git checkout`. Don't modify `tests/reference_data/`.
Don't refactor working, passing code — and note that increment E was reverted
for exactly that reason once its consumer disappeared.

## Lessons

1. **A residual is a hypothesis about where a defect is, with no more standing
   than a scoping list.** Measuring residual 34 found a defect four orders of
   magnitude larger in the same function, and a sibling path with the same bug.
2. **A measurement that says "X does not read Y" has located a seam, not
   cleared one.** The question is which function *does* read Y — and for the
   dipole caveat it was neither of the two the residual discussed.
3. **Two claims that look alike are not both load-bearing.** The C2 convention
   was applied in two places; removing it from the one the docstring named
   changed nothing, because the other had already done it.
4. **A presence check is not a drift guard.** Asking whether a name appears
   somewhere passed two injections. The assertion has to be agreement with the
   registry, and an enumeration that contradicts the prose beside it is worse
   than an omission.
5. **When the thing a generalization was for turns out to be unreachable,
   revert the generalization.** Keeping increment E would have meant carrying a
   parity regression and a falsified test for no capability.
6. **Ask whether the task is possible before asking whether it is hard.** The
   brief said to expect the route phases to be the hard part. They were
   unobservable, and the piece they were for was ruled out by a
   Frobenius–Schur indicator.
