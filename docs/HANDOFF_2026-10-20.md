## Conventions (unchanged, and they all earned their keep this session)

- Commit to `develop` after each increment with a green suite; stage files
  explicitly. **Ask before pushing.** Do not merge to `main` without asking.
  Sequence, with permission each time: push `develop`,
  `git merge --ff-only develop` onto `main`, push `main`, then
  `git pull --ff-only origin develop` and `git fetch origin main:main` on exxa.
- Every physics change gets a Fortran, analytic or finite-difference oracle —
  **never code-vs-code**.
- **A new oracle is not an oracle until you inject the bug it is meant to catch
  and watch it fail.** This caught four of my own mistakes this session.
- Tests: `/opt/anaconda3/envs/multi/bin/pytest tests/ -q -p no:cacheprovider`
- **Never run fits locally.** Use exxa; see the previous handoff for details.
- `pkill -f <pattern>` self-matches over ssh. Use `pgrep -f "foo[.]py"`.
- **Restore an injected bug from a file backup, not `git checkout`** — the
  latter reverts to HEAD and silently drops uncommitted work in the same file.
  It bit me once in B5-4; the tests caught it, but they need not have.

### Lessons that cost something this session

The previous handoff's eight still hold. These five are new, and four of them
are about **tests that passed when they should not have**.

1. **A harness is not an oracle until you have checked that the two things it
   compares are two things** (residual 45). B5-5's first attempt edited the
   emission *inside* the function the harness compared against, so both sides
   moved together: 25 tests passed and the gate proved nothing. What gave it
   away was implausibility — a 188-line restructure does not pass byte equality
   first try. The fix is structural (`emission='plan'|'legacy'` over a shared
   body) and there is now a **gate for the gate**: every plan-side emitter must
   run on the plan path and *not* on the legacy one. **Any new emitter needs a
   line there.**
2. **A lookup that falls back to a weaker match cannot validate the stronger
   one** (residual 46). A wrong dipole geometry passed every physics test
   because `_find_transi_block` fell through to a dimensions-only match. Until
   that fallback was disabled for declared symmetries, B5-7 was a *restatement*
   of the geometry rather than a use of it. **Ask of every new plan entry: if
   this were wrong, what would fail?**
3. **The text of a call is not evidence the call runs.** A test asserting
   `"actor_geometries.get(" in src` passed against an injection that replaced
   the enclosing `if` with `if False:`. Prefer capturing what a function is
   *handed* (monkeypatch and record) over reading source.
4. **A convention only exercised on a symmetric special case is untested, not
   correct** (residual 47). My spherical-to-Cartesian conversion put D3d's
   axial channel along (1,−1,−1); it was right for every z-axis group because
   there x and y never enter. When a change makes a previously-unreachable case
   reachable, expect the conversions *around* it to be wrong rather than merely
   untried. And **prefer rotating into the frame a trusted routine already works
   in over writing a new transform** — the new transform needs its own oracle.
5. **Measure the correspondence before implementing the group** (residual 48).
   Measuring that Td is Oh relabelled took twenty minutes and turned B5-9 from
   "add a group" into "add a label map", with an exact-equality oracle. It also
   stopped the exact agreement being mistaken for a bug later.

### 1. B5-5b — one emitter instead of two (optional, the last B5 item)

Route Oh through the D4h dispatcher with **Oh as its own target group**, so its
subduction step is the identity and `_make_oh_op_adds` / `_make_oh_dipole_adds`
retire. Split out of B5-5 deliberately: it changes **which code computes the
coefficients**, so byte equality becomes the claim rather than the check — if
the two routes disagree the fingerprint says they differ and nothing about
which is right. **Its oracle is the Ballhausen one-electron energies**, which
`tests/test_hamiltonian/test_cf_one_electron.py` already runs for both groups.
After B5-9 the loop is general without this; it is cleanup, not capability.

### 2. The other eleven groups — present, unreachable for want of *names*

**This is the item to read before anything else**, because the previous
handoff got the gate wrong and residual 49 corrects it.

All 14 WP-B target groups are registered with **complete and correct group
theory**: the right CF parameter count and ranks, derived dipole components and
weights, conventional Mulliken labels (13 of 14; T is the known exception).
Only Oh, D4h and Td have *store conventions*, so only those three are reachable
from `calcXAS`. See the **B-status table** in the plan.

**Their correctness is validatable today, with no new reference data.** Every
one of the 14 can express Oh's own cubic invariant to ≤ 9.4e-16, so each group's
invariant space is "Oh's cubic field plus distortions" — which makes the
**descent limit to Oh exact**, and Oh is Fortran-validated. WP-B2a already does
precisely this for D4h (the Oh limit at dt = ds = 0, cosine 1.0000000 against
all four fixtures); nothing about it is special to D4h. Residual 49 lists the
full cross-validation ladder — family invariants, the cubic-invariant
containment, the descent limit, the group-independent dipole sum rule,
subduction composition along a chain, and the LAPACK-scramble harness.

**What the ladder cannot settle is the names and the block order** — which
rank-4 trigonal invariant is `Dτ`, which rank-2 one `Dσ`, what strings ttrac
would write, in what order. A pure renaming is invisible to every test
available, which is exactly why it needs an external source and why B3 declined
to invent `(10Dq, Dσ, Dτ)`. **Do not guess them** — residual 39's trap.

**So there is a decision to take before starting the next group.** Either
expose a group under *derived, neutral* parameter names (the cubic invariant
plus `cf4_1`, `cf2_1`, … in `cf_invariant_vectors` order), fully validated by
the ladder, and add the conventional names later as aliases — or hold every one
of the nine behind WP-B6. Residual 49 recommends the first: it separates what
can be checked from what must be looked up, instead of holding correct and
checkable physics unreachable for want of a label.
