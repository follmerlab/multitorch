## Three findings that matter more than the three increments

### 1. `'correct'` is not the Fortran lineshape, and the lineshape has never been compared to it

`ttmult/src/spectra.c`, driven by `ttplo`, gives each line a **Fano** profile —
a normalised Lorentzian of HWHM γ in the q → ∞ limit the decks use — and
convolves it with a **discretely sampled** Gaussian renormalised by the sum of
its own weights. That is a true Voigt computed numerically. `1.36603` appears
**nowhere** in `ttmult/src/`, only at `pyctm/pyctm/get_spectrum.py:490`. Both
`broaden_mode` values are analytic approximations to something the Fortran
computes exactly, and the only end-to-end lineshape oracle this package has is
the eight pyctm `.xy` files. So the broadening layer rests on an
external-implementation oracle, which the conventions rank *below* Fortran.
`ttplo` is not built, but `widen_lines` and `convolute` are self-contained, so a
standalone C harness around `spectra.c`'s own two functions is the reachable
oracle. Residual 70.

### 2. The suite passes with 488 of d4h d7's ADD coefficients moved

Flipping the sign of the phase `_pin_d4h_routes` pins — inside the gauge
freedom, so every observable is untouched — moves 488 of 1303 entries, leaves
oh7/oh8/d4h8 bit-identical, and **1910 tests stay green**. A *different* cause
from increment E's operator reorder, which the narrow guard does now catch.
`test_generator_refactor_parity.py` cannot close it structurally: it compares
`generate_ledge_template` against the retained legacy function, two paths
*agreeing* rather than output being *unchanged*, and anything both consume moves
both. Hence `tests/golden/rac/`. Residual 71.

### 3. The d¹ dimension inference was wrong in three entries, two of them healthy irreps

Not just the pure-ligand-hole `1/2+` (`[0,37]` vs `[37]`): the lone block's
**ket** extent was appended as configuration 1's dimension for `fs['1/2-']`
(`[23,600]` vs `[600,600]`) and `fs['3/2-']` (`[45,1200]` vs `[1200,1200]`) —
final irreps reached from `3/2+` and `^1/2+` as well, where they carry real
intensity. A final manifold would have been sized 1200 instead of 623. Latent,
not shipped: the refusal fired before a RAC was built. Residual 72.

## What to be careful of

**`tests/golden/rac/` is a snapshot of our own output, not an oracle.** It
cannot establish that a coefficient is right — nothing does, for d4h d7 away
from the Oh limit. When it fires the coefficients *moved*, not necessarily
wrongly: check the gauge-invariant quantities first (Oh-limit fixture parity,
descent limit, dipole sum rule, LAPACK scramble), decide whether the movement
was intended, and only then re-bless with `tests/tools/bless_rac_golden.py`,
which prints how many entries moved so the number goes in the commit message.
`tests/reference_data/` remains the only Fortran oracle and is still never
modified. **This supersedes the 10-23 handoff's instruction to re-create an
ad-hoc dump before touching `rac_generator`** — the check is now a committed
test, though the dump remains the right tool for a case outside the four.

**d¹ charge transfer is reachable, not validated.** `hopping_blocks`' n = 1
entries have no Fortran oracle — no d¹ two-configuration fixture exists and
ttrac cannot be re-run. The V → 0 limit validates the metal block, the structure
and the dimensions, and says nothing about V ≠ 0. Say that to anyone running
Ti³⁺/V⁴⁺ LMCT.

**A comparison with one side pinned and the other defaulted is the failure class
SCA-001 exposed.** `test_d4h_ni_from_scratch_runs_and_matches_oh_baseline` built
one spectrum with `mode="legacy"` and the other from `calcXAS_cached`'s default
under the comment "broadened like calcXAS" — true until the default moved, after
which the cosine fell to 0.999718 against a `> 0.99999` floor. Nothing physical
changed; the two sides stopped sharing a lineshape. All four spectra there now
pin the mode explicitly.

**`pyproject.toml` carries a `filterwarnings` ignore for the SCA-001 notice.**
It exists so the suite stays warning-clean without churning ~30 mode-insensitive
call sites. **Remove it when the notice goes in 0.3.0**, along with the notice.

## Lessons

1. **Ask what the Fortran does before deciding what "correct" means.** SCA-001
   looked like a one-line default flip. The Fortran suite computes a numerically
   convolved Voigt and neither pseudo-Voigt mode is it, so the flip is an
   improvement on an analytic oracle and not a step toward parity — and the word
   `'correct'` will keep implying otherwise.
2. **A guard that looks like it covers a class may cover one cause.** The
   operator-order guard is real and has teeth, and the failure class around it
   was still wide open; a second cause in the same function passed 1910 tests.
3. **Measure where the thing you are about to drop actually sits.** The d¹
   ligand-hole manifold is 0.58 eV above the ground state at Δ = 1, not "at +Δ".
   Dropping it would have been numerically safe for a reason that is a fact about
   Δ > 0 and low T, not a structural one.
4. **A tolerance you cannot explain is a measurement you have not made.** 2.2e-07
   on float64 eigenvalues was a nearest-level matcher picking ligand-hole levels;
   separating the configurations gave 7.1e-15, and the same comparison at a
   physical Δ reads 5.9 eV.
5. **Blessing a snapshot while an injection is live freezes the injection.**
   Restore from the file backup and re-verify the digests *before* writing a
   golden file.
6. **Running finds sites that reading does not.** Lifting the d¹ refusal exposed
   three more places with the same assumption, including a second range guard
   that the residual's own text never mentions.
